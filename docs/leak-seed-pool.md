# 漂移种子池：旧的反复漏、新的漏不出来

状态：**诊断已定稿（v3），4.1 / 4.2 / 4.4 已落地，4.3 待 Q1 拍板**
实测对象：`ysj` 实例，2026-09-03 15:10
数据来源：sidecar 图库（8741）、`.fakeren-knowledge/ysj.json`、`/tmp/fakeren-prestep.log`

> **实现时发现的两处偏差（v3 写的方案不落地，已就地更正，见 §4.1 / §4.2）：**
> 1. L0.5 冷却**不能取 24h** —— `l05FreshDays=1`，24h 冷却套在 24h 新鲜窗口里
>    等价于"每条知识只漏一次"，正是要修的旧行为。改为 **6h**（§4.1）。
> 2. §4.2 的 `exp(-(now - edge.createdAt)/τ)` **算不出来** —— 边上没有时间戳，
>    而 §7 规定不动 sidecar 存储结构。改用"静默轮数"做饥饿权重（§4.2）。
> 3. §4.4 的 idle 缓存**没做** —— 过滤掉 live 会话后，pre-step 只会对已关闭会话
>    调用 `loadSessionEvents`，而它对已关闭会话本来就能成功，缓存层是多余的
>    新状态。改为"显式跳过 + 记 `histSkipped`"（§4.4）。

## 0. 先说 v2 错在哪（必须记录，否则会重犯）

v2 提出了一组"需求冲突"：2026-08-29 的要求「同一个会话里相同的记忆
不需要反复的漏」与「新知识要持续漏出」冲突，需要用户裁定取舍。

**用户一句话推翻了这个框架：**

> 我现在看到的是旧的知识在不断的漏，也就是只漏一次根本就没生效，什么都没挡住；
> 新的知识一次都没漏，也就是新知识的学习使用这个流程本身有 bug 了，哪里和哪里有冲突？

**这个反驳是对的，而且指出了我犯的错的类型。**

我把两个现象分别归因：
- "旧的在漏" → 我 v1 就知道 crossDomain 无去重，但 v2 里把它降级成
  「断点四（次要）· 排序让最老的永远占位」，理由是"转得再匀也是漏不该漏的"——
  **我只把它理解成"排序均匀度"问题，没看到它是"去重规则缺失"问题**
- "新的不漏" → 我归因于 once-per-session"太严"
- 然后宣布两者冲突，把选择权甩给用户

但真相是：**once-per-session 只存在于 L0.5 通道，crossDomain 通道压根没有去重。**
所以两个现象不是两个需求在打架，是**同一条需求在两个通道上实现得一半过度、一半缺失**：

| 通道 | 需求的实现状态 | 用户看到的现象 |
|---|---|---|
| crossDomain | **完全没实现** | 旧知识每轮都漏（"什么都没挡住"） |
| L0.5 | **实现了，但过度**（一次即死） | 新知识漏 1 次后永久消失（"流程有 bug"） |

**没有冲突需要裁定，只有一处 bug 需要修。**

这也是继 v1「目标总体选错」之后同一种错误的第二次发作：
**用一个漂亮的框架（规则冲突、需要用户拍板）掩盖了我没看清楚的因果。**
每当我想把选择题甩给用户时，应该先问：是不是我自己没查到底。

## 2. 真正的根因

### 2.1 去重规则在两条通道上不对称

```ts
// src/channels/drift-channel.ts —— crossDomain：零去重
const seeds = await this.reader.crossDomain(instanceId, 200);
seeds.slice(0, this.leak.driftLimit);   // 每轮重新 gather，无跨轮状态

// src/knowledge/l05-trajectory.ts:26-30 —— L0.5：一次即死
if (this.sessionLeaked.get(sessionId)?.has(fact.id)) continue;   // 漏过即永久排除
```

sidecar 的 `cross_domain()`（`server.py:190`）也**没有任何排序**，
按 `self._edges` 插入顺序返回 → 池子是时间正序 → `slice(0,3)` 取的永远是
最老的 3 条 → 那 3 条旧知识因此获得了**永久席位**。

### 2.2 自我锁死循环（二阶效应，这是"流程有 bug"的实质）

```
新知识学到
  → 不入图（daily-tracker 无写图调用），只能走 L0.5
  → 漏 1 次，被 sessionLeaked 永久排除
  → 再也不漏 → 假人在回复里永远不提它
  → 抽取器扫不到 → 永远入不了图
  → 永远进不了 crossDomain 那條唯一没有去重的通道
  → 锁死
```

而旧知识能循环，恰恰是因为它在 `sessionLeaked` 生效之前就**绕后门入图**了
（知识漏出 → 假人回复提到 → 该轮被抽取器扫到 → 成为节点 → 进跨域池 → 无去重 → 每轮漏）。

**所以「只漏一次」这条规则做了一件事：它精确地把唯一能漏出新知识的通道掐死，
同时完全不管旧知识的循环。** 这不是"过严"，这是装错了地方。

### 2.3 附带：跨域池里装的多数是「不该漏的东西」（v2 保留，仍成立）

69 条 `crossdomain_weak` 边中 **57 条（83%）由 `LlmExtractor` 产出**。
它拿到的输入**只有一轮对话**，却被要求标注「弱跨域联想」——**单轮视野在原理上
无法判断「域」**，于是退化成「同域共现」：淳于髡↔王斗、苏秦↔影子、南郭先生↔竽声。

设计意图写得很清楚（`ambient-leakage-framework.md` §2.1）：
> 你早上读到的新闻，会在下午完全不相关的对话里悄悄改变你的措辞

跨域污染的**主体是假人自己学到的知识**，不是聊天里出现过的人名。

## 3. 为什么不存在冲突（回答"哪里和哪里有冲突"）

2026-08-29 的要求是：「同一个会话里相同的记忆不需要反复的漏」。

- 在 **crossDomain** 上，这条要求**从未被实现** → 这就是"旧的不断漏"
- 在 **L0.5** 上，它被实现成"一次即死"，**超出了要求本身** → 这就是"新的漏不出来"

**要求是同一条，问题不是它自相矛盾，是它在两条通道上实现得不一致。**

修法因此不是"二选一"，而是**把两侧调到同一个机制**——冷却窗口：

| 通道 | 现状 | 改为 |
|---|---|---|
| crossDomain | 每轮都漏（0 冷却） | 冷却窗口内不重复 |
| L0.5 | 漏 1 次永不再漏（∞ 冷却） | 冷却窗口内不重复 |

两侧统一后：
- 旧知识不再每轮刷屏 ✅ 满足 2026-08-29 的要求
- 新知识冷却期后可再漏 ✅ 满足"新的要漏得出来"
- **不需要撤回任何既有要求，不需要用户做取舍**

## 4. 修复方案

### 4.1 【主】两条通道统一用冷却窗口

`DriftChannel` 需要跨轮状态（现在完全无状态）。引入统一的冷却语义：

```
可用条件：now - lastLeakedAt > cooldownMs
权重    ：recency × random         （recency = exp(-(now - createdAt)/τ)）
```

| 通道 | `cooldownMs` 默认 | 理由 |
|---|---|---|
| crossDomain | **10 轮**（或 30 分钟，取先到） | 现在是 0 轮 → 必须收紧 |
| L0.5 | **6h**（⚠️ 不是 v3 写的 24h，见下） | 必须显著小于 `l05FreshDays` |

> ⚠️ **落地更正 —— L0.5 冷却 24h 是一个空修复**
>
> `l05FreshDays` 默认是 1：知识只有 24h 的候选寿命。若冷却也设 24h，则
> 「新鲜窗口 ∩ 冷却窗口」= 每条知识最多漏 **1 次** —— 和旧的 once-per-session
> **完全等价**，用户报的"新的漏不出来"一个字节都不会变。
>
> （v3 §1.3 自己写过"freshness 从未成为瓶颈"，但没顺着往下推一步：
> 一旦冷却拉到与 freshness 同量级，freshness 立刻变成唯一的闸门。）
>
> 取 **6h**：24h 新鲜窗口内容纳 ~4 次浮现（0h / 6h / 12h / 18h）——看得见，
> 又远不是"每轮都漏"。已加守卫用例（§5 用例 2b）锁住这个关系。

改后预期对照：

| 项 | 现状 | 改后 |
|---|---|---|
| 普雷斯顿 / 科索沃 | 各 **20/40 轮** | 冷却期内不再重复，长期会话中偶尔回访 |
| 3 条新知识 | 各 **1 轮** | 24h 新鲜窗口内约 **4 次**，通道不静默 |

### 4.2 【主】crossDomain 加权轮转 ✅ 已落地（公式已更正）

冷却只解决"不重复"，还需解决"新的有机会"——池子按插入顺序 = 时间正序，
`slice(0,3)` 永远取最老的。改为按权重采样。

> **落地更正 —— recency 算不出来，改用饥饿权重**
>
> v3 原式 `edge.weight × exp(-(now - edge.createdAt)/τ)` 依赖边的创建时间，
> 但 **sidecar 的边不存时间戳**（`server.py` 的 `cross_domain()` 只返回
> from/to/kind/weight/props），而 §7 规定"不动 sidecar 的图存储结构"。
>
> 改用 TS 侧算得出来的量 —— **静默了多少轮**：
>
> ```
> idle   = 距上次漏出的轮数（从未漏过 = cap）
> weight = edge.weight × (1 + idle/cap) × rng()      cap = 冷却轮数 = 10
> ```
>
> 效果与 recency 一致且更强：它直接奖励"还没漏过的边"，而新知识进池后
> 正是"没漏过的边"，于是天然获得约 2× 权重，不必依赖时间戳。

同时删掉假标签：溯源字符串 `crossDomain by |valence| rank N` 中
`props.valence` 从未被写入（全为 `None`），`minValence` 默认 0（门槛关闭），
这个 rank 恒等于插入顺序。改为：

```
crossDomain weighted-rotate (w=0.42, idle=new)     ← 未漏过
crossDomain weighted-rotate (w=0.31, idle=7t)      ← 静默 7 轮
```

**并删除 `minValence` 配置项**（留着只误导下一个排查的人）——
`src/leak/config.ts` 与 `scripts/inspect-core.mjs` 同步删除。

### 4.3 【语义】`LlmExtractor` 停止产出 `crossdomain_weak` ⏸ 未落地（等 Q1）

单轮视野判断不了「域」，这是**原理性缺陷，不是调参问题**。
抽取器只保留 `relates` / `causal`；`crossdomain_weak` 仅由 `consolidate` 的元簇机制产出。

> 本批**没有实施**这一条：它会把跨域池从 69 砍到 ~12，漏出密度显著下降，
> 属于 Q1 待确认项。4.1/4.2 已经止住了"旧知识刷屏"，这条不紧急。
> 等用户一句话确认再动（§5 的用例 10-12 也一并搁置）。

⚠️ **副作用**：跨域池从 69 条缩到 12 条左右。按定义这是**正确的收缩**
（对话内容不该漏），但会显著改变漏出密度（见 Q1）。

### 4.4 【本批】往昔回放恒为 0 ✅ 已落地（做法已简化）

`loadSessionEvents` 在 live 会话下 `catch → return []`，静默失败；
而 `DriftChannel.gather` 每轮都必然失败地调用它一次。

> **落地更正 —— 不需要 idle 缓存层**
>
> v3 提议"把已关闭轮次的摘要在 idle 时缓存进 registry"。实现时发现多余：
> `loadSessionEvents` 只对 **live** 会话必然失败，对已关闭会话是好用的。
> 把当前会话从回放列表里剔除之后，pre-step 只会调用注定成功的那些，
> 缓存层只是凭空多一份需要失效的新状态。
>
> 实际做法：
> 1. `sessionIds.filter(sid => sid !== sessionId)` —— live 会话直接跳过；
> 2. 跳过数记进 `counts.histSkipped`，日志里 `hist=0` 因此**能被解释**
>    （"有 1 个会话因为本轮还没关闭被跳过"），而不是看起来像"这个人没有过去"。

### 4.5 【可选】知识入图

学习成功时把 fact 写成 `Entity` 节点（`props.kind = "knowledge"`）。

**v2 曾把它当成打破锁死的关键，那是错的**——4.1 修好后 L0.5 本身就是畅通的
知识主通道，不必绕道 crossDomain。入图的真正价值是让知识能被 **recall 通道**
检索到（目标导向），属另一个通道，不在本批范围。

## 5. 测试用例

> 落地位置：`tests/leak-cooldown.test.ts`（19 例，全绿）。
> 用例 10-12（跨域语义）随 4.3 一并搁置。
> 变异验证：跨域冷却 `turns:10→0` → 5 例红；L0.5 冷却 `6h→24h` → 4 例红
> （含用例 2b/3）；去掉 live 会话过滤 → 3 例红。测试确实咬得住这个 bug。

**去重对称性（核心，直接回归用户报告的两个现象）**

1. **旧的不反复**：同一 `sessionId` 连续 40 轮，任一跨域边在连续 10 轮内不重复出现
   —— 现状是每轮都出现（20/40 轮），必然失败
2. **新的不消失**：知识在冷却期后可再次漏出
   —— 现状是漏 1 次后 67 轮不再出现，必然失败
2b. **冷却必须显著小于 `freshDays`**：24h 新鲜窗口内知识浮现 ≥3 次且 <24 次
   —— 若有人把冷却改回 24h，这条立刻红（守卫 §4.1 的那个更正）
3. **回归用户报告的现象**：模拟一个 12 小时未关闭的长期会话（40 轮），
   断言知识种子浮现 ≥2 次（实测 `[0, 20]` 两轮）
4. 两条通道使用同一个冷却实现（断言共享 `LeakCooldown`，防二次漂移）

**L0.5（5 例）**

5. `freshDays` 硬门槛仍生效：超过天数的知识不进候选
6. recency：刚学的知识权重高于 7 天前学的
7. `status=empty` 的记录永不进候选（现有行为，防回归）
8. 加权随机的分布：同一候选池跑 1000 次，每条都被选中过（无饿死）
9. 会话级冷却隔离：新 `sessionId` 重置计数

**跨域语义（3 例）**

10. `LlmExtractor.parse` 遇到 `kind: "crossdomain_weak"` 时降级为 `relates`
11. 抽取器产出的边集合不含 `crossdomain_weak`
12. `consolidate` 仍能产出元簇的 `crossdomain_weak` 边

**轮转与溯源（2 例）**

13. 连续 10 轮 gather，跨域种子不完全重复，且新近边有机会入选
14. 溯源字符串不含 `by |valence| rank`；`minValence` 配置项已移除

**往昔回放（2 例）**

15. live 会话下 gather 不调用 `loadSessionEvents`（断言调用次数为 0）
16. idle 缓存为空时，日志明确记录 `hist=0` 而非静默
