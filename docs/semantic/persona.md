## 1. 谁是用户

| 层级 | 用户 | 说明 |
|---|---|---|
| 第一用户（当下） | **Sai 本人** | 实验台 + 第一道人感评审关。工程洁癖，要求可观察、可复现、可审计；反感黑盒与"看起来像"的取巧实现。设备边界：个人 macOS 跑通即可。 |
| 目标群体（终局） | **大众** | 期望假人朝**真正的电脑助手**方向发展——不是小说写作插件，而是一个有环境态、会漂移、有个体历史的日常助手。 |

**⚠️ 这条定位是本次画像最大的信息增量**：前几轮讨论的落点一直隐含在"写作人感"上，
现在终局用户是大众日常助手，直接引出一个必须在阶段二解决的真冲突 —— 见 §4。

**待解决痛点**：现有 agent 输入 relevance-gated → 输出 relevance-shaped，太连贯、太切题、
太服务目标，读作"AI"；缺少来自其他方面对潜意识的影响变量。

## 2. 成功判据（两级门禁，顺序不可换）

1. **机制层面正确**（第一优先，硬门）——否则"还是风味 AI"。落成不可违背规则 `rule_mechanism_first`：
   - 禁 fabricated 种子；ambient 必须非目标导向（漏而非查）；每条种子可溯源到真实外部事件。
   - **宁可效果弱，也不许用编造内容凑人感**；任何"看起来像有潜意识"的取巧实现视为失败。
2. **真人使用体验与评价**（第二级）——落成 `rule_human_eval_gate`：
   - 先过 Sai 自己这关（他觉得没问题）；
   - 再推荐给其他人试用、收集评价。
   - 工程含义：**必须内建可比较的体验开关（ambient on / off）+ 种子溯源展示**，否则无法评价。

## 3. 平台与分发边界

- 本轮不重要：**只需 Sai 个人设备（macOS）能用**。
- 不做：多平台适配、打包分发、多用户隔离、运维监控、CI/文档站。
- 但因终局面向大众：**单用户假设不得写进核心**（架构不堵死这条路，成本为零的克制而非提前实现）。

## 4. 首轮范围

- **一次性到位**：L0 / L0.5 / L1 三层一起搭，不分版本迭代、不做上线发布规划。
- 个人研究项目，落成成本约束 `cost_scope_one_shot`。
- **明确一点**：一次性到位 ≠ 跳过阶段三架构评审。三层同时上线意味着模块边界必须先设计清楚，
  否则三层会互相污染（尤其 L0 漂移与 L1 注入抢同一个 prompt 预算）。

## 5. 成功画面（定稿）

- 假人在日常使用中被一层**真实但无关**的环境态潜移默化影响，产出偶然、有来路、略微跑偏的联想。
- 每一处"污染"都能指回具体真实事件 / Wiki 条目 / 新闻条目——不是 incoherent 噪声。
- ambient on / off 对照下，Sai 主观判定 on 更"活"，且机制经得起他自己的审查。

## 6. 由本画像直接引出的阶段二议题（预告）

1. **助手定位 × ambient 漏出的冲突**：创作任务里"跑偏"是活气，执行任务（查资料/改代码/操作文件）
   里"跑偏"是错误。需要 leak 策略按任务类型分级，还是全局统一？
2. **L0 基质采集面**：只用 dsh 会话事件日志（窄但绝对真），还是也接本机真实非任务信号
   （日历 / 文件活动 / 时间 / 天气）？后者更"真富"但涉本机隐私采集。
3. **可观察性规格**：漂移过程要做到什么程度可见（这是"机制正确"能否被审查的前提）。
4. **人评设施是否算 M**：ambient on/off 开关 + 溯源展示，是必须还是想要。
