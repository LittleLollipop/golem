# 漂移种子池：新学的知识漏不出来

状态：**已修正诊断，待评审**（v2，推翻 v1）
实测对象：`ysj` 实例，2026-09-03 14:40
数据来源：sidecar 图库（8741）、`.fakeren-knowledge/ysj.json`、`/tmp/fakeren-prestep.log`

---

## 0. 先说 v1 错在哪（必须记录，否则会重犯）

v1 统计了「今天写入的 61 个节点有多少进了跨域池」，得出 16% 覆盖率，
并据此提出「近因回响」独立源——把图里最新的节点拉进来当种子。

**这个方向是反的。** 那 61 个节点绝大多数是**对话中抽取的实体**（南郭先生、
湣王、孟尝君田文、乐毅、钟无艳、夏迎春），而用户明确指出：

> 我跟它聊的部分并不需要可以漏出来，那个不是跨域的，需要漏的是新学的知识

所以「近因回响」会放大**恰恰不该漏的东西**。

**错误根因：没有先界定「漏出的对象总体」就去量化通过率。** 拿一个无关总体
算出 16%，再照着它设计修复，等于精确地解决了一个不存在的问题。

设计意图其实写得很清楚（`ambient-leakage-framework.md` §2.1）：

> 你早上读到的新闻，会在下午完全不相关的对话里悄悄改变你的措辞

跨域污染的**主体是假人自己学到的知识**（L0.5），不是聊天里出现过的人名。
本文档按这个定义重做诊断。

## 2. 四处断点

### 2.1 断点一（根本）：跨域池里装的全是「不该漏的东西」

`crossdomain_weak` 边有 83% 由 `LlmExtractor`（`src/memory/llm-extractor.ts:21`）产出。
它拿到的输入**只有一轮对话**（`用户说：X / 助手答：Y`），却被要求标注
「弱跨域联想（不同领域之间的微妙牵连）」。

**单轮视野在原理上无法判断「域」。** 模型只能把它退化成「这一轮里任意两个
感觉有点关系的实体」，于是产出：

- 淳于髡 ↔ 王斗（同一部小说的两个角色）
- 苏秦 ↔ 影子（同一段讨论）
- 南郭先生 ↔ 竽声（同一个典故）

这些是**同域共现**，不是跨域。整个池子 69 条边，绝大多数是对话内部的粘连。

> **结论：跨域池的内容本身就不符合「跨域」的定义。排序问题只是让这个错误
> 更刺眼——即便加了轮转，漏出来的仍然是对话内容。**

### 2.2 断点二：知识根本不入图

`src/knowledge/daily-tracker.ts` **没有任何写图调用**。`LearnedFact` 只流向两处：

1. `golem-remote.ts:216 getKnowledgeRecords` —— 给 UI 的知识标签页看
2. `l05-trajectory.ts seedCandidates` —— L0.5 漂移种子

那 3 条进了图的知识（普雷斯顿、科索沃市镇、楠塔哈拉鎮區）是**绕后门进去的**：
知识先经 L0.5 漏出 → 假人在回复里提到它 → 那一轮对话被抽取器扫到 → 才成为节点。

**知识只能是「先漏后入图」，顺序是反的。** 而一旦会话里没聊到它，就永远不进图。

### 2.3 断点三：知识唯一的泄漏通道被三重闸门掐死

L0.5 是知识唯一的漏出口，同时受三个限制：

| 闸门 | 配置 | 默认值 | 后果 |
|---|---|---|---|
| 新鲜度 | `FAKEREN_LEAK_L05_FRESH_DAYS` | **1 天** | 只有 24h 内学的算数 |
| 每轮条数 | `FAKEREN_LEAK_L05` | **2** | 一次最多 2 条 |
| **每会话去重** | `sessionLeaked`（硬编码） | **每条知识整场会话只漏 1 次** | 漏完即死 |

学习速率 ≈ 1 条/天，且 14 次尝试里 6 次失败 → 实际约 0.6 条/天。

**实测结果（用户抱怨的直接来源）**：整场会话共 **80 个 LEAK BLOCK，其中只有
3 个含知识种子 —— 3.75%**。三次分别是 09-01 楠塔哈拉、09-02 忙哥帖木儿、
09-03 凯耶达尔。**其余 96% 的轮次，用户看到的只有那 3 条 08-30 的跨域边。**

两个附加事实，它们决定了修法的边界：

- **`sessionLeaked` 是纯内存 `Map`**（`l05-trajectory.ts:29`），进程重启即清空。
  开发期反复重启 dsh 掩盖了问题的严重性。
- 真正的约束是 **`freshness ∩ once-per-session` 的交集**。单独放宽 freshness
  只是一次性补货：门槛放到 7 天会一次性放出 5 条此前未在本会话漏过的旧知识
  （普雷斯顿 / 科索沃市镇 / 烤過頭 / Virtual iPhone / 盧映錡），但它们各漏
  一次之后通道**再度静默**，长期会话里不可持续。

### 2.4 断点四（次要）：排序让最老的永远占位

`DriftChannel.gather` 每轮重新 gather，**无跨轮去重、无轮转、无随机**：

```ts
const seeds = await this.reader.crossDomain(instanceId, 200);
seeds.slice(0, this.leak.driftLimit)   // driftLimit = 3
```

而 sidecar 的 `cross_domain()`（`sidecar/server.py:190`）**没有任何排序**，
直接按 `self._edges` 插入顺序返回。

附带一个误导：溯源日志写 `crossDomain by |valence| rank N`，但 `add_edge`
从未写入 `props.valence`（全部为 `None`），而 `minValence` 默认 0（门槛关闭）。
**这个「rank」恒等于插入顺序，是假标签。**

## 3. 优先级判断

| 只修哪个 | 能否解决「新学的知识漏不出来」 |
|---|---|
| 断点三 之 **freshness** | ⚠️ **只是一次性补货** —— 放出 5 条旧知识后通道再度静默 |
| 断点三 之 **once-per-session** | ✅ **这才是真正的闸门** —— 但它是一条明确的用户要求（见下方冲突） |
| 断点四（排序轮转） | ❌ 无效 —— 池子里装的仍是对话内容，转得再匀也是漏不该漏的 |
| 断点一（跨域语义） | ⚠️ 必要但不够 —— 它只能**止血**（停止错误标记），不能让知识漏出来 |
| 断点二（知识入图） | ❌ 单独无效 —— 入图后仍需跨域边才能漏，而跨域边的语义本来就是坏的 |

**→ 主线是断点三；断点一是语义正确性，同批做；断点四顺带；断点二降级为可选项。**

### ⚠️ 必须先解决的规则冲突

`l05-trajectory.ts:26-30` 记着一条**明确的用户要求**（2026-08-29）：

> 同一个会话里相同的记忆不需要反复的漏

这条要求被实现成了「每条知识整场会话只漏 1 次」。而长期会话场景下，
它与「新学的知识要持续漏出来」**直接冲突**：会话不关闭就永远补不进新知识。

**这不是实现细节，是需要重新裁定的规则。** 三个选项见 Q1，我不自行决定。

## 4. 修复方案

### 4.1 【主 · 待裁定】L0.5 的去重规则

三个选项，**Q1 需要用户拍板**。共同部分是先把 freshness 门槛放宽
（24h → 7d），真正的衰减交给连续的 recency 权重，而不是硬切割。

#### 选项 A：冷却窗口替代「一次即死」（推荐）

把「每会话一次」改成「**N 小时内不重复**」。`cooldownMs` 默认 24h。

```
weight(fact) = recency(fact) × (now - lastLeakedAt > cooldownMs ? 1 : 0)

recency(fact) = exp(-(now - learnedAt) / τ)     τ 默认 3 天
```

- 保留了 2026-08-29 要求的**精神**：短时间内不会「反复漏」同一条
- 但长期会话里，过了冷却期的知识可以再出现一次，通道不会永久静默
- 与「新知识优先」叠加后，实际观感是：新知识频繁、旧知识偶尔回访

#### 选项 B：衰减重复

每条知识带 `leakCount`，权重按 `decay^leakCount` 衰减，永不归零。

```
weight(fact) = recency(fact) × decay^leakCount(fact)     decay 默认 0.5
```

- 通道永不静默，且天然抑制重复
- ⚠️ 与 2026-08-29 的字面要求（「不需要反复的漏」）**直接冲突**，需用户明确撤回

#### 选项 C：维持一次即死，只放宽 freshness

- 完全不触碰既有要求，改动最小
- ⚠️ 但只是**一次性补货**：5 条旧知识各漏一次后通道再度静默，
  长期会话里问题会原样复现。**不解决用户报告的现象**，仅作保守兜底

#### 效果对照（按当前 8 条已学知识，选项 A / B）

| 项 | 当前 | 选项 A / B |
|---|---|---|
| freshness 硬门槛 | 24h → 约 2 条候选 | 7d → **8 条全部可选** |
| 单条知识能漏几次 | **1 次**（整会话） | A: 每 24h 一次 / B: 无限但权重减半 |
| 长期会话里通道静默 | **是（96% 轮次无知识）** | 否 |
| 会不会反复漏同一条 | —— | 不会：冷却 / 衰减 + 加权随机 |

新增配置：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `FAKEREN_LEAK_L05_FRESH_DAYS` | 1 → **7** | 硬门槛放宽（连续衰减交给 recency） |
| `FAKEREN_LEAK_L05_TAU_DAYS` | **3** | recency 指数窗口 |
| `FAKEREN_LEAK_L05_COOLDOWN_H` | **24** | 选项 A 的冷却窗口 |
| `FAKEREN_LEAK_L05_DECAY` | **0.5** | 选项 B 的每次衰减（B 未选中则忽略） |
| `FAKEREN_LEAK_L05_LIMIT` | 2 | 不变 |

### 4.2 【语义】`LlmExtractor` 停止产出 `crossdomain_weak`

单轮视野判断不了「域」，这是**原理性缺陷，不是调参问题**。
抽取器只保留 `relates` / `causal`；`crossdomain_weak` 仅由 `consolidate` 的元簇机制产出。

⚠️ **副作用需要确认**（见 Q1）：跨域池会从 69 条缩到 12 条左右。
按用户的定义（对话内容不该漏），这是**正确的收缩**；但它会显著改变漏出的
整体密度，需要观察。

### 4.3 【次要】跨域池加权轮转 + 会话内冷却

`DriftChannel` 需要跨轮状态（现在完全无状态）。

- 会话内冷却：漏过的边进入冷却集，N 轮内不再取（N 默认 10）
- 加权随机：`weight = edge.weight × exp(-(now - edge.createdAt)/τ)`
- 溯源字符串改掉假标签：去掉 `by |valence| rank N`，改成
  `crossDomain weighted-rotate (w=0.42, cooled=false)`
- `minValence` 及其门槛**删除**（跨域边从未写入 valence，留着只误导下一个人）

### 4.4 【可选】知识入图

学习成功时把 fact 写成 `Entity` 节点（`props.kind = "knowledge"`）。

**降级理由**：入图后仍需跨域边才能漏，而 4.2 已经把跨域边的口子收紧了。
真正的价值在于让知识能被 recall 通道检索到（目标导向），那属于另一个通道，
不在本批范围。

### 4.5 【本批】往昔回放恒为 0

`loadSessionEvents` 在 live 会话下 `catch → return []`，静默失败；
而 `DriftChannel.gather` 每轮都必然失败地调用它一次。

改法：把「已关闭轮次」的摘要在 idle 时缓存进 registry，pre-step 只读缓存，
不再调用 live 会话接口。缓存未就绪时**明确记录 0 条**而不是静默返回。

## 5. 测试用例

**L0.5 去重规则（8 例，按 Q1 选中的选项启用对应分支）**

1. 选项 A：漏过一次的知识在 `cooldownMs` 内不再出现；**超过冷却期后可再次出现**
2. 选项 B：单条知识可重复漏出，`leakCount` 递增、权重按 `decay` 衰减
3. **回归用户报告的现象**：模拟长期会话（同一 sessionId 连续 80 轮，
   期间按 1 条/天新增知识），断言**任意连续 20 轮内至少出现 1 次知识种子**
   —— 现状是 80 轮只出现 3 次且集中在前中段，必然违反
4. recency：刚学的知识权重高于 7 天前学的
5. `freshDays` 硬门槛仍生效：超过天数的知识不进候选
6. `status=empty` 的记录永不进候选（现有行为，防回归）
7. 加权随机的分布：同一候选池跑 1000 次，每条都被选中过（无饿死）
8. **不反复**：任意连续 5 轮内，不出现同一条知识（守住 2026-08-29 要求的精神）

**跨域语义（3 例）**

9. `LlmExtractor.parse` 遇到 `kind: "crossdomain_weak"` 时降级为 `relates`
10. 抽取器产出的边集合不含 `crossdomain_weak`
11. `consolidate` 仍能产出元簇的 `crossdomain_weak` 边

**轮转与冷却（3 例）**

12. 连续 10 轮 gather，跨域种子不完全重复
13. 冷却期内的边不进入候选；冷却期过后可再次入选
14. 溯源字符串不含 `by |valence| rank`

**往昔回放（2 例）**

15. live 会话下 gather 不调用 `loadSessionEvents`（断言调用次数为 0）
16. idle 缓存为空时，日志明确记录 `hist=0` 而非静默

## 7. 本批不做的事

- **不动 `GROWTH_PROB` / `consolidate`** —— 元簇机制不是主要矛盾
- **不动 sidecar 的图存储结构** —— 4.3 的排序放在 TS 侧做，Python 侧不动
- **不给漂移通道加「近期节点回响」源** —— v1 的错误方案，会放大对话内容
- **不碰 recall / 处境通道** —— 三通道隔离不变量（`ambient-leakage-framework.md` §5）
