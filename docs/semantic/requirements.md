### 两条决策的结构性后果（必须写在这里，阶段三要用）

**① L1 重定义 → 架构从"两通道"变"三通道"。**
原本 L0/L0.5/L1 都被当作同一条「非目标漏出」通道的成员。现在 L1 的目标是**理解**（服务用户），
不是**污染**（制造人感）——它允许被有意识使用。所以必须拆成三条互不借道的通道：

| 通道 | 成员 | 是否目标导向 | 用途 |
|---|---|---|---|
| 漂移通道 | L0 真实史 + L0.5 知识轨迹 | **否**（漏而非查） | 人感：偶然、有来路的跨域污染 |
| 处境通道 | L1 用户处境 | **可以是**（有意识用） | 共情/理解：用户此刻面对什么 |
| 图检索通道 | recall | 是 | 事实：目标导向图检索（非向量 RAG） |

**② 真感官接入 → 早前判定"结构性不可达"的富潜意识，重新可达。**
前几轮我的结论是"无身 agent 没有身体、没有鸡，鸡→鸟 boss 那种富潜意识结构性不可达，只能要真实但窄的生活"。
接了摄像头 / 麦克风之后这条限制被打破：环境光线、是否有人在场、环境声、时段氛围
——**这些是真实的、非机器制造的、非目标导向的**，完全满足禁 fabricated 纪律，且是无身 agent 逼近真实具身的唯一路径。

**③ 宿主模态不可知 → 信号源边界下放。**
阶段二结尾我提的「核心须限制麦克风只取环境特征、摄像头只取粗粒度」被否决：那是核心越界规定模态语义。
正确分层是——宿主只管「信息能否进来（`req_capture_whitelist` 开关）+ 存哪（`req_local_only`）+ 能否关停」，
而「进来的是什么、能用到什么程度（是否转录 / 识别）」是**扩展组件自己的责任与边界**。
这条原则保证未来可加任意感官（味觉 / 监听类等）而不改核心。

## 三处我必须直说的技术张力（阶段三要给出解法，不是现在拍）

1. **输出级归因（C2）技术上只能近似，且天真做法会违反禁编造纪律。**
   让模型自己说"我受了乌鸦那条影响"= 模型编故事，正是 `rule_mechanism_first` 要禁的。
   唯一可验证的做法是**反事实重跑**：同 seed 同参数，一次带种子一次不带，对输出做 diff。
   代价是每次评测要跑两遍 → 建议**评测模式常开、日常模式只留 C1（记注入了什么）**，
   这正是你说的"不行再向下调整标准"的具体降级路径。

2. **任务分级会误判，须定 fail-safe 方向。**
   "构思架构方案"（强漏）和"执行命令"（零漏）在真实对话里常常连着发生（先想再做）。
   分类器必然有误判。建议：**不确定时按严谨（零漏）**——宁可少一点灵气，不可污染执行。

3. **信号源边界下放给扩展组件，核心保持模态不可知。**
   阶段二结尾我提过「核心须限制麦克风只取环境特征、不做转录」——这被否决：那是核心越界规定模态语义。
   正确分层：宿主只管「信息能否进来（`req_capture_whitelist` 开关）+ 存哪（`req_local_only`）+ 能否关停」；
   「进来的是什么、能用到什么程度（是否转录 / 识别）」是**扩展组件自己的责任与边界**，包括它自己决定是否做转录。
   这条原则保证未来可加任意感官（味觉 / 监听类）而不改核心。但宿主仍须守住铁律：
   **任何源不可达 → 降级无注入**（`req_degrade_no_fabricate`），绝不编造填补。
