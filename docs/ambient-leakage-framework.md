## 0. TL;DR

人类文本里的"活气"——不连贯、略微跑偏、被无关经历污染出的新奇联想——来自潜意识层面的环境影响：**联想启动（associative priming）** 与 **情境认知（situated cognition）**。当前 agent 的上下文注入是 **relevance-gated（相关性门控）** 的：只有显式对话 + 目标导向检索能进 prompt，于是输出被 relevance 塑形成"切题、服务目标、零冗余"，这恰好是"AI 声纹"。

本框架主张在运行时补一层 **非目标导向、概率性、缓慢漂移的环境态 priming 通道**，作为与"检索通道"正交的独立信号源；并用一套**可审计 = 非编造**的纪律约束它，使其产出"带环境态"的候选而不退化成幻觉式人设。框架与具体 harness / 模型 / 存储解耦，可移植。

---

## 1. 现象与问题：relevance-gated 输入如何制造"AI 声纹"

考虑一个最小例子。用户问：

> "周末想出去走走，附近有啥推荐？"

**relevance-gated baseline** 的输出大致是：

> "您附近有 XX 公园（评分 4.6）、XX 美术馆（当前有印象派特展）。需要考虑亲子 / 独行 / 天气吗？我可以帮您规划路线。"

正确、切题、服务目标、逻辑连贯、零冗余——**这正是"AI 感"的声纹**。人类真实的回答往往不是这样：

> "嗯……我上周扭了腰，爬楼还隐隐的。不过昨天刷到说西郊那片芦苇现在正黄，想着要不骑车去吹风发呆就行，不爬了。"

后者的"活气"来自三件 baseline 没有的东西：(1) 一段**与当前问题弱相关但真实发生过**的身体状况（L0）；(2) 一条**今天偶然看到、并非为回答而检索**的信息（L0.5）；(3) 二者**非目标导向地**污染了回答，产生了"不爬了"这个 baseline 绝不会给出的、却更人性的转向。

关键点：**这不是"检索不到相关信息"，而是"根本没有通道去承载那些不相关但塑造了你'的东西"**。加更多数据、更好的 prompt、更强的模型，都不会自动长出这一层——因为它在定义上就不属于 relevance-gated 输入。

## 2. 理论假设

### 2.1 联想启动（associative priming）

认知心理学中，近期接触过的概念会无意识地偏置后续表达（spreading-activation 传统的核心结论）。 priming 效应是低概率、无意图、跨域的：你早上读到的新闻，会在下午完全不相关的对话里悄悄改变你的措辞。

### 2.2 情境认知（situated cognition）

理解发生在具体处境里，而非抽象目标中。一个人的"此刻状态"——疲劳、环境光照、刚发生的琐事——持续调制其表达，且多数调制与人类当下目标无关。

### 2.3 综合命题

> **人感 = 在低概率、与目标正交的方向上，被真实历史持续污染的生成分布。**

当前 agent 缺的不是"更好的检索"，而是"一个与目标无关的、缓慢漂移的真实历史偏置源"。

## 3. 形式化：渗漏通道作为一个偏置项

把生成建模为在目标条件分布上叠加一个环境态偏置：

```
log p'(w | goal, ctx) = log p(w | goal, ctx) + λ_leak · g(w ; Ω_t)
```

- `p(w | goal, ctx)`：标准 relevance-gated 生成（baseline）。
- `Ω_t`：时刻 t 的**环境态**，由 L0/L0.5 漂移通道构造，**其采样分布与 goal 无关**。
- `g(w ; Ω_t)`：环境态对词 w 的 priming 函数（Ω 中的概念激活其联想邻居）。
- `λ_leak`：任务相关的漏出强度（见 §6）。

对比检索增强：检索通道引入的是 `g(w ; R)`，其中 `R = retrieve(goal)`——**R 是 goal 的函数，因此偏置天然朝向 goal**。"渗漏"与"检索"的本质区别就在 `Ω ⟂ goal`：

- 检索：环境由目标决定 → 偏置与目标共线 → 输出更切题 → 人感死。
- 渗漏：环境独立于目标 → 偏置引入与目标正交的方差 → 偶然的跨域污染 → 人感生。

我们用**双候选**落地：同时生成 `p'`（带环境态）与 `p`（纯净），由选择器 `σ` 据任务类型裁决（§6）。

## 4. 三层环境影响框架（机制级）

### 4.1 L0 个体潜意识层

**种子来源**：agent 真实发生过的事——真实对话、决策、用户真实上下文、真实动作后果；并接入真实感官（摄像头 / 麦克风）。

**提取机制**：以 append-only 事件日志为真实史基质（每条 model-visible 行为必 logged，杜绝 fabricated 种子）。从日志中抽取"非对话目标导向"的片段作为 L0 种子——例如"用户昨晚提到腰伤""环境光照变暗"。感官流不转录为对话，而是沉淀为**环境纹理**（ambient texture）：一种低语义、高情境的真实存在感。

**连续性编织**：机器只负责把 L0 种子按时间 + 因果边编织成连贯的"自我漂移"，**绝不发明种子**。偶然性（contingency）是人感的真 ingredient；任何 authorial intent 都会被嗅出（§8.2）。

**泄漏示例**：用户问爬山 → L0 种子"腰伤"经 `g(·;Ω)` 激活"不爬 / 缓行 / 吹风"等邻居 → 输出出现 baseline 不会有的"不爬了"转向。

### 4.2 L0.5 知识轨迹层

**选择器算法**（核心，非随便学）：
1. 取真实排名源（Google / Wiki）的 **top1**；若 top1 已在知识史中 → 取 **top2**，依此类推（拥抱排名偏差，不"纠正"）。
2. **反 trending 过滤**：剔除纯热点 / 文化属性强的条目（热点会引入"群体人设"而非"个体轨迹"）。
3. **慢节奏**：每日至多 1 条，模拟个体学习节律。
4. **学习史即选择器**：已学条目构成"这个人关心什么"的轮廓，反过来影响未来 top-N 的落点。

**审计轨迹 schema**（每条习得强制）：
```
{ acquired_at, source_url, rank_position, chosen_because, prior_knowledge_id }
```
`rank_position` + `chosen_because` 保证可指回真实世界事件/Wiki 条目——这是"非编造"的硬保证。

### 4.3 L1 用户处境理解层

**与 L0/L0.5 的本质区别**：L1 可被**有意识调用**，且**允许与漂移通道走相反方向**。它不污染，而是"理解"——用户此刻面对什么世界事件、可能受何影响。这引出三通道隔离（§5）。

## 5. 三通道架构与隔离不变量

| 通道 | 成员 | 目标导向 | 用途 |
|---|---|---|---|
| **漂移通道** | L0 + L0.5 | 否（漏而非查） | 人感：偶然、有来路的跨域污染 |
| **处境通道** | L1 | 可以是 | 共情 / 理解：用户此刻面对什么 |
| **图检索通道** | recall | 是 | 事实：目标导向图检索（非向量 RAG） |

**隔离不变量（核心）**：漂移通道的输入分布必须满足 `P(Ω) ⟂ goal`。一旦 Ω 的构造引入任何 goal 条件（"为了回答这个问题，我漏点相关的"），漂移通道立即退化为检索通道，人感死。**三条通道互不借道**是这个框架能否成立的结构性前提。

---

## 6. 漏出双层控制（机制）

**第一道 · 执行前分级**——按任务类型映射 `λ_leak`：

| 任务类型 | λ_leak | 理由 |
|---|---|---|
| 对话 / 创作 / 构思 | 强 | 人感是主目标 |
| 事实查询 | 弱 | 保真优先 |
| 执行命令 / 改代码 | 零 | fail-safe 朝严谨 |

**第二道 · 执行后后筛**——生成双候选 `p'`（带环境态）与 `p`（纯净），由选择器 `σ` 裁决：
- 默认：创作/对话取 `p'`，执行/代码编辑取 `p`。
- 歧义时**交用户选**——双候选设计的目的正是保留用户代理权，而非用单一调参替用户决定"有多像人"。

## 7. 记忆基底：per-instance 图记忆

### 7.1 为什么必须是图数据库：长程注意力的根本矛盾

不论模仿人的思维还是处理大型任务，agent 都同时需要两种看似矛盾的注意力：**对核心需求的长程高度注意力**（跨越多步、多轮始终锚定"到底要解决什么"），以及**对当前分支任务的足够全面的了解**（在当下这一步掌握完成任务所需的全部相关上下文）。二者最终都落在同一载体——**上下文**上，而上下文对信息的要求是"**即多又少**"：

- **多**：当前分支所需的背景、约束、前置结论必须充分在场，缺一则推理断裂；
- **少**：与核心需求无关的信息必须被压住，否则注意力被稀释，长程目标在噪声中迷失。

"多"保证当前步能落地，"少"保证长程不跑偏，是同一枚硬币的两面，却必须由同一份输入同时承载。

**单轮提示词的天花板。** 无论何种提示词策略——精心设计的 system prompt、长上下文窗口、结构化摘要、压缩重述——都无法在**单轮信息输入**中同时满足"多"与"少"。这并非技巧不足，而是结构上的不可能：要"多"就得把相关材料尽量塞进上下文，但塞得越多、无关占比越高、长程锚点被稀释；要"少"就得事先筛选，而筛选依赖"什么是相关的"这一判断，该判断又依赖更上层的上下文——递归无解。换言之，**相关性判断所依赖的上下文，与相关性筛选要呈现的上下文，是同一份**：单轮输入无法既当裁判又当选手。

**现有方案只是转移矛盾。** RAG 召回、循环执行（agentic loop）、工作流（multi-agent orchestration）都是对这一矛盾的回应，但共同局限是**没有消除矛盾，只是把矛盾拆分、转移给了不同的 agent**：RAG 把"多"外包给检索，可检索相关性仍依赖 query，而 query 质量受限于当前上下文；循环执行把"长程"拆成多步，每步仍是单轮，长程锚点在传递中持续衰减；工作流 / 多 agent 把"全面"拆给不同职责的 agent。于是出现可观察的退化：**任务越复杂，越需要分化出更多 agent 处理不同层级、不同目的的需求**，代价是巨大的 token 浪费——这些 agent 之间**只是工作目的不同，实际所拥有的上下文高度相似**（读同一份 ground truth，只是各自取用切片不同）。分化没有减少"信息即多又少"的矛盾，只是把它复制到了 N 个并行的单轮。

**理论最优解与其黑盒陷阱。** 结构上能同时满足"多"与"少"的是**多轮交互 + 向量数据库**：多轮让"少"得以维持（每轮只注入当前所需，长程靠轮次间状态延续而非一次性堆砌），向量库让"多"得以按需召回（按语义相似度拉回相关部分）。但这一组合落地撞上另一堵墙：**向量库的使用是纯黑盒，近似于炼丹**——相似度质量高度依赖 embedding 模型、切分策略、索引参数，皆经验性、难预测，难以稳定保证"核心需求相关的一定在场、无关的一定被压住"。想要完美实现"即多又少"，在向量库路径上异常困难。

**形态上模拟思维的图库：真正的最优选择。** 权衡落在第三种形态——**在结构上可模拟思维的图库（knowledge graph）**。图天然表达"关系"与"层级"：节点是事实 / 概念 / 事件，边是因果、时序、归属、引用，恰好对应人类记忆的组织方式——不是把记忆平铺成一袋向量，而是按关联织成网络，回忆时沿边遍历、按需展开。相比向量库，图库的优势不在"更聪明的相似度"，而在**可解释、可控制、可组合**："多"由遍历保证（从当前分支节点出发沿边扩展一两跳即拉回相关上下文，范围由边类型与深度显式界定）；"少"由结构保证（无关子树根本不在遍历路径上）；长程锚点显式常驻（核心需求作为高权重、被反复引用的节点持续存在）；全程可审计（每条边的来由、每次展开的轨迹都可追溯，不存在"为什么召回这条"的黑盒问题）。

因此在本框架中，这一选择具象为 **typed edges（source / temporal / causal）的图记忆**：它既承接上述"长程注意力 + 分支全面性"的根本矛盾之解，又额外满足本框架的纪律要求——(1) **溯源边**使每个种子可指回真实事件，满足可审计纪律（§8.3）；(2) **因果边**支撑连续性编织而非拼接；(3) **可观察**使漏出来源 human-readable。向量 RAG 的相似度检索本质是 relevance-gated（§3），与漂移通道正交性要求冲突，且其"炼丹"式调参不可观察、不可溯源——这正是本框架弃向量而取图的根本理由。

**per-instance 隔离**：每个"个体"（假人）持有独立的 Ω，随时间各自漂移 → 自然涌现出"个体历史"。这正是多假人系统的记忆层设计：隔离是默认，而非配置项。

### 7.2 与分层记忆方案的比对：结构上限在关系拓扑

分层记忆（L0/L1/L2…，或 working / long-term tiers）在本框架中并非对立物，而是**一种退化图**——它在图论上等价于一个有界深度的 DAG：

- 节点角色由 schema 预设（层数 L 固定，通常 3–4）；
- 唯一的边是层间"晋升 / 检索"，且同质（不区分因果 / 时序 / 来源）；
- 跨层路径数 = L−1，是个小常数。

因此"分层记忆相当于结构预设好、链路数量固定的图"这一理解是准确的。图记忆则是节点 + typed 边，拓扑随内容生长、路径数不预设。

**同效区间。** 当任务的关系复杂度低时——相关上下文靠"选对层 + 近期性"即可取到，关系主要是线性 / 顺序的——分层与图几乎等效，且分层更省（无遍历、无 embedding 开销）。"一定规模内效果相同"成立。

**结构上限究竟卡在哪（关键修正）。** 上限**不在事实数量，而在关系 / 拓扑保真度**。分层靠摘要压缩可以无限扩事实量（"记得 X 发生过"永远可行），但保不住事实之间的**关系结构**。具体在三点咬人：

| 维度 | 分层记忆的失败模式 | 图记忆的对应解法 |
|---|---|---|
| 关系保真 | 唯一边是晋升 / 检索（同质），遥远关系只有被摘要漏斗"抓住"才存活，否则丢失 | typed 边（causal / temporal / source）把**关系本身**存下来 |
| 长程锚点存活 | 顶层是固定容量全局仓，容量压力下按近期性 / 重要性淘汰 → 核心需求锚点可能被丢 | 锚点靠**入边引用权重**常驻，与近期性无关 |
| 跨分支缝合 | 当前分支要组合两个无共同摘要路径的事实时缝不上 | 经共享锚点**多跳遍历**，自然缝合 |

**回到 §7.1 的"多 / 少"框架。** 图给"多"= 遍历按需展开一两跳；给"少"= 无关子树根本不在遍历路径上。分层给"多"= 固定漏斗一次性注入，代价是 distant-relation 的"少"保真度被牺牲。因此"结构层面有上限"是对的，更精确地说：**上限在关系拓扑，不在事实体量**；它出现在"关系复杂度 > (L−1) 条固定晋升通道能保留的量"这一档任务。

**现实注脚。** golem 本身已是混合体：L0/L0.5/L1 是层（快路径工作集），per-instance 记忆是图（关系型长期存储）。二者并非二选一——分层当 cache，图当关系真相源。§7.1 的论点实际是"**关系型长期结构应由图承载**"，而非全盘否定分层。

## 8. 方法论红线（含机理）

1. **非目标导向扩散，不是检索**——机理见 §3/§5：Ω 与 goal 正交是结构性前提，违反即退化。
2. **L0 种子须真实史基质，禁 fabricated**——凡机器制造的内容都带 authorial intent；coherence 救不了，只会更像"高级 AI 感 / 换了种风格"。人类能嗅出"这转折太巧了、太有设计了"。
3. **可审计 = 非 fabricated**——每条种子带 source_url + rank_position + chosen_because（§4.2 schema）。溯源边是信任的硬基础设施，不是装饰。
4. **调 leak rate**——λ 过大 → 噪声干扰、偏离任务；λ 过小 → 无效、与 baseline 无异。需 spike 调（§10）。
5. **拥抱排名偏差，勿"纠正"**——Wiki / Google 排名的流行度 / SEO 偏差是真实世界的 prior；"纠正"会 reintroduce 作者意图，把偶然性偷换成设计。

## 9. 与既有工作的关系（定位 novelty）

| 工作 | 记忆？ |  drift 通道？ | 与本框架差异 |
|---|---|---|---|
| Mem0 / Letta | 有，但 relevance-gated 检索 | 无 | 缺独立的环境态偏置源 |
| Character.AI / 角色扮演 | persona 脚本 | 无 | 人设是写死的，不从真实历史涌现 |
| Reflection / inner-monologue | 自我改进 | 无（仍 goal-oriented） | 仍是目标导向的自我提升 |
| persona / world-model prompting | 静态人设 | 无 | 不漂移、不演进 |
| **本框架** | per-instance 图记忆 | **有（L0/L0.5 正交偏置）** | 非目标导向渗漏 + 可审计纪律 + 实例漂移 |

**真正的 novelty 三点**：(a) 把"非目标导向渗漏"作为一等通道而非 prompt 技巧；(b) 用可审计纪律让它可信而非幻觉式人设；(c) per-instance 漂移使"个体历史"自然涌现。

## 10. 验证协议（让 claim 可证伪）

框架必须可被证伪，否则只是主张。设计：

- **盲测 A/B**：同等任务质量下，盲评者对 `p'`（带环境态）vs `p`（纯净）打分。指标：拟人度评分、turn 级 engagement、连贯性保持率、"意外但正确"率（surprise-but-right）。
- **控制变量**：用同一 base model，仅切换 λ_leak ∈ {0, 弱, 强}，排除模型差异。
- **证伪条件**：若 `p'` 在相等任务质量下未显著优于 `p` 的 engagement / 拟人度 → 假设失败，需重新建模 Ω。
- **leak-rate sweep**：扫描 λ 找最优区间（指标出现单峰则存在最优；单调则假设需修正）。

---

## 11. 失败模式与开放问题

- **渗漏坍塌**：λ 过大 → 输出变噪声、偏离任务。
- **漂移失稳**：Ω 漂移过快 → 个体"人格"一年一变，失去可信连续感。
- **隐私 / 感官责任**：L0 接摄像头/麦克风 → 个人玩酷，做产品是合规雷区。
- **多用户记忆隔离 bug**：per-instance 串味 → 甲的历史漏进乙。
- **被基础模型吸收**：大厂把"记忆+语境+人格"烤进基座 → 薄插件层护城河被抹平（缓解：框架与调参经验仍可授权）。

---

## 12. 诚实边界

- **已验证（个人尺度）**：三层模型在个人日常使用中稳定产出"更有人感"的表达；双候选 + 漏出分级在创作/执行场景未失控。
- **待验证（规模化前必做）**：§10 盲测 A/B、λ 最优区间 spike、per-instance 漂移在多用户 + 隐私监管下的部署。
